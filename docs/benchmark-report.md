# ED-DRLE Local Benchmark Report

## Scope and method

These are the only committed load-test results used for performance claims.
Each result was generated by a script under `bench/` and stored with its
timestamp, commit, environment, status counts, and raw latency samples.

All three runs are **local-in-memory** on Windows x64, Node.js `v22.17.1`, and
a 12th Gen Intel Core i5-1235U with 12 logical CPUs. The regular workload
submits 500 reserve requests in sequential batches of 50. It bypasses local
rate limiting and uses in-memory repositories; it does not measure Redis,
PostgreSQL, DynamoDB, LocalStack, or AWS.

## Interpretation

The standard workload is the same shape across the first two runs, but the
recorded source commits differ. The logging-change run has lower throughput
and higher p95/p99 latency than the baseline, despite a lower p50. These
results do **not** establish an apples-to-apples performance improvement or
prove that the logging change caused any particular metric change.

The hot-key run is a separate workload, not a direct baseline comparison.
Profiling in the performance phase pointed to structured logging, JSON
serialization, console output, and fetch/HTTP overhead in the local test path.
That is local bottleneck evidence only; it is not proof of the AWS bottleneck.

The README's former `229.67 RPS` / `315 ms p95` claim had no committed
provenance and has been removed. The repository has no qualifying AWS load
test. The 10,000 RPS figure is a stated target, not a measured result.

## Reproduction and evidence rules

Use the scripts above, preserve each raw JSON result under `bench/results/`,
and record the exact commit and environment for any new run. Keep local and AWS
results in separate reports. Do not copy the transient load output printed by
`npm test` into a performance claim: it is not the committed `/bench` result
format or a commit-qualified experiment.
